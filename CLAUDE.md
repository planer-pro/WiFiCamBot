# CLAUDE.md

Проект PlatformIO (Arduino): плата на модуле **ESP32-S3 N16R8** + съёмный модуль
камеры **OV2640** от классической ESP32-CAM. Камера стримит MJPEG на веб-страницу
по WiFi. Один исходник — `src/main.cpp`.

## Команды

```bash
pio run -d .                  # сборка
pio run -d . -t upload        # прошивка (плата по USB, порт /dev/ttyACM0)
pio run -d . -e ota -t upload # прошивка по WiFi — ArduinoOTA (esp32cam.local)
pio device monitor -d .       # монитор порта (115200)
```

## Железо и критичные решения

- **N16R8 = 16 МБ quad-flash + 8 МБ octal-PSRAM**: в `platformio.ini` обязательно
  `board_build.arduino.memory_type = qio_opi`, `board_upload.flash_size = 16MB`,
  `board_build.partitions = default_16MB.csv` и `-DBOARD_HAS_PSRAM`. Не убирать —
  иначе PSRAM не инициализируется и стрим деградирует.
- **lib_deps пуст намеренно**: драйвер `esp32-camera` уже встроен в ядро
  arduino-esp32 2.0.17 (precompiled в SDK платформы espressif32). Библиотеку из
  реестра не добавлять — она устаревшая и помечена `frameworks: espidf`.
- **Пины камеры** (блок «ПИНЫ КАМЕРЫ» в начале `src/main.cpp`) — распиновка
  Freenove ESP32-S3-WROOM CAM по умолчанию. Точная модель платы пользователя
  неизвестна: если камера не инициализируется — менять нужно только этот блок
  (таблица и ссылки в README).
- **RGB-светодиод** — WS2812 на GPIO 48 (подтверждено на плате пользователя
  тестом с кнопками). Отправка — собственный драйвер `wsSendColor()` через RMT
  (`driver/rmt.h`, канал 0, тик 50 нс). Штатный `neopixelWrite()` ядра 2.0.17
  этот светодиод НЕ зажигает (пин при этом верный) — на него не возвращаться.
- **Отладки (Serial/LOG) в коде нет** — удалена по просьбе пользователя: на этой
  плате вывод прошивки в монитор не доходит (стартовый ROM-лог приходит), что
  проверено минимальным скетчем и прямой записью в FIFO USB — дело не в коде
  проекта. Возвращать не предлагать.

## Устройство кода

- Сервер — `esp_http_server` из ESP-IDF, **два экземпляра**: порт 80 — `/` и
  `/set?quality=|light=|color=`, порт 81 — только `/stream`. Поток httpd у
  каждого экземпляра один, а `stream_handler` — бесконечный цикл: держать
  стрим на одном сервере с `/set` нельзя (пока открыт стрим, остальные запросы
  этого сервера не обслуживаются — из-за этого «не работали» кнопка света и
  качество; проверено на железе). Страница строит абсолютный URL стрима
  `http://<host>:81/stream` в JS — относительной ссылки на другой порт нет.
  Стрим можно открыть и напрямую (VLC и т.п.): `http://esp32cam.local:81/stream`.
- Качество (разрешение + jpeg_quality) — таблица пресетов `QUALITY_PRESETS`,
  применяется на лету `applyQuality()` без переинициализации камеры. Пресеты
  только 4:3 — из-за CSS-поворота страницы.
- Свет — таблица `LIGHT_COLORS` + `applyLight()` → `wsSendColor()` (RMT);
  состояние `g_lightOn`/`g_lightColor`, меняется через `/set?light=|color=`.
- Страница `INDEX_HTML`: подстановка текущих значений вместо меток `@Q@`/`@L@`/`@C@`
  в `index_handler` (chunked-ответ, с заголовком `Cache-Control: no-cache` — чтобы
  после перепрошивок браузер не держал старый JS). Список цветов в HTML обязан
  совпадать с `LIGHT_COLORS` по индексам.
- Страница поворачивает кадр на 90° по часовой стрелке средствами CSS
  (`.stage` с аспектом 3:4, угол меняется в `INDEX_HTML`).
- Камера: JPEG, 2 буфера в PSRAM, `CAMERA_GRAB_LATEST`.
- **OTA-прошивка по WiFi** — ArduinoOTA (встроен в ядро, UDP-порт 3232): init в
  `setup()` после `startWebServer()`, `ArduinoOTA.handle()` в `loop()`. mDNS у
  библиотеки отключён (`setMdnsEnabled(false)`): её `begin()` поднял бы второй
  mDNS и сломал `esp32cam.local` — служба `_arduino._tcp` добавляется вручную
  через `MDNS.enableArduino(3232)` в уже работающий mDNS. Прогресс обновления
  дублируется RGB-светодиодом (`onStart`/`onProgress`/`onEnd`/`onError` —
  Serial-отладки на плате нет). Пароль необязателен: `OTA_PASSWORD` в
  `wifi_secrets.h` + `upload_flags = --auth=…` в env `ota`. Прошивание — env
  `ota` в `platformio.ini` (`upload_protocol = espota`); `default_envs =
  esp32s3_cam`, чтобы `pio run -t upload` без `-e` не лез по сети. Разделы
  `ota_0`/`ota_1` уже есть в `default_16MB.csv` — таблицу разделов не менять.
  Проверено на железе: OTA при открытом стриме работает (кадры замирают на
  время записи, потом всё продолжает).

## Подводные камни (проверено на этой версии ядра)

- Имена enum — `CAMERA_FB_IN_PSRAM` / `CAMERA_FB_IN_DRAM` (не `CAMERA_PF_*`).
- `STREAM_BOUNDARY` — это `#define`-макрос, а не `const char[]`: он
  склеивается со строковыми литералами при компиляции.
- В хэндлерах после `esp_camera_fb_return(fb)` поля `fb` читать нельзя —
  сохранять нужное (`len`) до возврата буфера.
- Ошибка `esp_camera_init` `0x20004`/`0x105` — почти всегда чужая распиновка.
- Один поток httpd на экземпляр сервера: незавершающийся хэндлер (`/stream`)
  блокирует ВСЕ прочие запросы этого сервера, а не только своё соединение —
  поэтому стрим вынесен на отдельный порт 81 (см. «Устройство кода»).
- Буферы кадра выделяются под `frame_size` на момент `esp_camera_init`:
  камера инициализируется под максимальный пресет (UXGA), а стартовый уровень
  применяется сразу после (`applyQuality(QUALITY_DEFAULT)` в `initCamera`).
  Без этого переключение вверх по разрешению (уровень 4) подвешивает стрим —
  проверено на железе.
- Открытие `/dev/ttyACM0` дёргает RTS и сбрасывает плату, а после такого
  сброса HTTP-сервер может молчать (пинг и mDNS при этом отвечают). Лечится
  чистым сбросом: `python3 ~/.platformio/packages/tool-esptoolpy/esptool.py
  --port /dev/ttyACM0 --chip esp32s3 --after hard_reset chip_id` и ожиданием
  ~30 с. Порт без нужды не открывать.
- OTA и USB-прошивку можно чередовать без «старого слота»: после OTA плата
  грузится из `ota_1`, но USB-заливка pio пишет и `boot_app0.bin` (otadata),
  возвращая загрузку на `ota_0`.
