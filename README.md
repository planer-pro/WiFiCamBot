# WiFiCamBot

Плата на модуле **ESP32-S3 N16R8** (16 МБ flash, 8 МБ PSRAM) + съёмный модуль
камеры **OV2640** от классической ESP32-CAM. Программа захватывает изображение
с камеры, подключается к домашнему WiFi и отдаёт веб-страницу с живым видео
(MJPEG-стрим).

## Настройка WiFi

Сеть выбирается на самой плате через **WiFiManager**:

1. Включите плату. Если сохранённая сеть не находится (первый запуск, смена
   роутера, неправильный пароль) — плата поднимет настроечную точку доступа
   **wificambot-setup** (имя задаётся `WIFI_AP_NAME` в `src/wifi_secrets.h`;
   в этом режиме RGB-светодиод горит синим).
2. Подключитесь к этой точке с телефона или ноутбука — страница выбора сети
   откроется сама (captive portal); если нет — зайдите на `http://192.168.4.1`.
3. Выберите свою сеть, введите пароль и нажмите Connect — плата запомнит их
   в энергонезависимой памяти и перезагрузится уже в вашей сети.

Потеря связи в работе лечится сама (автоподключение), а если сети нет дольше
30 секунд — плата перезапускается и при неудаче снова поднимает настроечную
точку.

Файл `src/wifi_secrets.h` (в git не попадает, добавлен в `.gitignore`) хранит
только имя настроечной точки доступа и (по желанию) пароль OTA — сеть и её
пароль нигде в коде не задаются, плата запоминает их сама:

```bash
cp src/wifi_secrets.h.example src/wifi_secrets.h
```

```cpp
#define WIFI_AP_NAME "wificambot-setup"
```

## Сборка и прошивка

```bash
pio run -t upload          # прошивка
pio device monitor         # монитор порта (115200)
```

- Плата подключается USB-кабелем; используется встроенный USB-Serial-JTAG
  ESP32-S3 — обычно порт `/dev/ttyACM0`.
- Если доступ к порту запрещён, добавьте себя в группу: `sudo usermod -aG dialout $USER`
  и перелогиньтесь.
- Отладки в коде нет (на этой плате вывод прошивки в порт всё равно не доходит —
  приходит только стартовый лог загрузчика ROM).

## Прошивка по WiFi (OTA)

Когда прошивка с OTA уже залита по USB хотя бы один раз, дальше плату можно
обновлять без кабеля — прошивка принимается по WiFi (ArduinoOTA, UDP-порт 3232):

```bash
pio run -e ota -t upload
```

- Адрес платы задан в env `ota` файла `platformio.ini` (по умолчанию
  `wificambot.local`; если имя не резолвится — подставьте IP платы).
- Прогресс дублируется RGB-светодиодом платы: синий — начало приёма, от
  красного к зелёному — ход обновления, зелёный — успех (после него плата сама
  перезагрузится), красный — ошибка.
- По желанию включается пароль: раскомментируйте `OTA_PASSWORD` в
  `src/wifi_secrets.h` и `upload_flags = --auth=…` в env `ota`. Без пароля
  залить прошивку сможет любой участник вашей WiFi-сети.
- OTA и USB можно чередовать: таблица разделов `default_16MB.csv` содержит два
  слота приложений (`ota_0`/`ota_1`), OTA-обновление пишется в свободный слот,
  а прошивка по USB сама возвращает загрузку на первый слот.
- Обновляться можно и при открытом стриме — на время записи во flash кадры
  ненадолго замирают, это нормально (проверено).

## Как найти адрес камеры

По имени mDNS (в Linux должен стоять avahi — в большинстве дистрибутивов есть):

```bash
avahi-resolve -n wificambot.local
```

Либо посмотрите список DHCP-клиентов в админке роутера и найдите новое
устройство (имя хоста `wificambot`).

## Адреса

| URL | Что делает |
|-----|-----------|
| `http://<IP>/` | страница с живым видео (порт 80) |
| `http://<IP>:81/stream` | «сырой» MJPEG-поток — порт 81, можно открыть в VLC |
| `http://<IP>/set?quality=N` | качество: 0 — минимальное … 4 — максимальное |
| `http://<IP>/set?light=1` | RGB-светодиод: 1 — включить, 0 — выключить |
| `http://<IP>/set?color=N` | цвет светодиода: 0 белый, 1 красный, 2 оранжевый, 3 жёлтый, 4 зелёный, 5 голубой, 6 синий, 7 пурпурный |
| `http://<IP>/set?rot=N` | поворот кадра на странице: 0 / 90 / 180 / 270 градусов |
| `http://<IP>/set?motor=X` | моторы гусениц: `f` вперёд, `b` назад, `l`/`r` повороты (разворот на месте), `s` стоп |
| `http://<IP>/set?speed=N` | мощность моторов вперёд/назад, % (1-100) |
| `http://<IP>/set?tspeed=N` | мощность поворотов, % (1-100) — отдельно |

На странице есть переключатель качества (от QVGA 320x240 до UXGA 1600x1200),
применяется на лету без перезагрузки платы, а также кнопка **«Свет»** и рядом
выпадающий список цвета для RGB-светодиода платы (по умолчанию белый). Для
гусениц — пульт-крестовина под видео (кнопки удерживать, клавиши — стрелки
и WASD, работает в любой раскладке) и две мощности: отдельно вперёд/назад и
отдельно повороты. Рядом с качеством — список «Поворот кадра» (0/90/180/270°):
страница поворачивает кадр CSS-ом, сцена меняет пропорции под угол — без
чёрных полей, с рамкой. Все эти настройки (качество, поворот, свет и цвет,
обе мощности) плата
сохраняет в энергонезависимой памяти (NVS) — они переживают отключение
питания и перепрошивку, а при открытии страницы в браузере подставляются
текущими значениями. Картинка
на странице повёрнута на 90° по часовой стрелке средствами CSS (как изменить
угол — комментарий в `INDEX_HTML` в `src/main.cpp`).

Светодиод — адресуемый WS2812 на пине `RGB_LED_GPIO_NUM` в `src/main.cpp`
(48 — Espressif DevKitC-1 и платы Freenove; подтверждён на этой плате тестом,
38 — старые ревизии DevKitC-1). Отправка кода WS2812 — собственный драйвер
`wsSendColor()` через RMT: штатный `neopixelWrite()` ядра arduino-esp32 2.0.17
этот светодиод не зажигает. Таблица цветов — `LIGHT_COLORS`, она должна
совпадать с `<option>` в `INDEX_HTML`.

Качество по умолчанию — «среднее» (VGA 640x480); меняется правкой
`QUALITY_DEFAULT` или таблицы `QUALITY_PRESETS` в `src/main.cpp`.

## Моторы гусениц (MX1508)

Робот — гусеничная платформа, драйвер моторов **MX1508** по танковой схеме:
канал A (IN1/IN2) — левая гусеница, канал B (IN3/IN4) — правая. Питание
моторов — отдельное, GND общий с платой. Повороты — разворот на месте
(гусеницы в противоположные стороны). Если плата не получает команд 1,5 с,
моторы останавливаются сами — при обрыве WiFi или закрытии вкладки робот
не уедет.

| MX1508 | GPIO | Куда |
|--------|------|------|
| IN1 | 1 | левый мотор, вперёд |
| IN2 | 2 | левый мотор, назад |
| IN3 | 3 | правый мотор, вперёд |
| IN4 | 14 | правый мотор, назад |

Пины меняются в блоке «МОТОРЫ ГУСЕНИЦ (MX1508)» в `src/main.cpp`. Если
гусеница крутится не в ту сторону — поменяйте местами пару пинов её канала
(IN1<->IN2 или IN3<->IN4).

### Зарезервировано под будущее I2S (не занимать)

| GPIO | Роль |
|------|------|
| 21 | DATA (микрофон / DIN усилителя) |
| 41 | BCLK |
| 42 | WS/LRCL |
| 38, 39, 40, 47 | запас (второе I2S-устройство, PDM-микрофон и т.п.) |

### Свободно

| GPIO | Комментарий |
|------|-------------|
| 43, 44 | UART0 TX/RX — последовательный порт не используется, пины свободны (плата подключена нативным USB на GPIO 19/20, UART-моста нет) |

### Не использовать

| GPIO | Причина |
|------|---------|
| 0 | strapping (режим загрузки) + кнопка BOOT на плате |
| 19, 20 | USB D−/D+ — разъём платы: прошивка по проводу и питание |
| 45, 46 | strapping (напряжение SPI-flash / режим загрузки) |
| 22-25 | на ESP32-S3 физически не существуют |
| 26-32 | шина SPI-flash (16 МБ) внутри модуля |
| 33-37 | шина octal-PSRAM (8 МБ, R8) внутри модуля |

Итого из 43 существующих выводов: занято 19, под I2S зарезервировано 7,
реально свободны 43/44. SD-карта не планируется — пины под неё не
резервируются (наследие ESP32-CAM задействовало бы GPIO 2/4/12/13/14/15,
они уже заняты камерой и моторами).

## Если у вас другая плата (камера не инициализируется)

Пины камеры по умолчанию заданы для **Freenove ESP32-S3-WROOM CAM** — это самый
распространённый вариант плат ESP32-S3 с 24-пиновым разъёмом под модуль камеры
от ESP32-CAM:

| Сигнал | GPIO | | Сигнал | GPIO |
|--------|------|-|--------|------|
| XCLK   | 15   | | D0 (Y2) | 11 |
| PCLK   | 13   | | D1 (Y3) | 9  |
| VSYNC  | 6    | | D2 (Y4) | 8  |
| HREF   | 7    | | D3 (Y5) | 10 |
| SIOD (SDA) | 4 | | D4 (Y6) | 12 |
| SIOC (SCL) | 5 | | D5 (Y7) | 18 |
|        |      | | D6 (Y8) | 17 |
|        |      | | D7 (Y9) | 16 |

Если ваша плата другая и в мониторе видна ошибка
`Ошибка инициализации камеры: 0x...`:

1. Найдите распиновку камеры для вашей платы — в примере производителя
   (обычно скетч `CameraWebServer`/`CameraWebServerApp` из поставки к плате)
   или в её схеме.
2. Замените значения в блоке «ПИНЫ КАМЕРЫ» в начале `src/main.cpp` — больше
   нигде менять ничего не нужно.
3. Полезные ссылки: [репозиторий espressif/esp32-camera](https://github.com/espressif/esp32-camera)
   (список распиновок популярных плат в примерах), [issue #802](https://github.com/espressif/esp32-camera/issues/802)
   про 24-пиновый разъём OV2640.

## Устранение неполадок

| Симптом | Причина / решение |
|---------|-------------------|
| `Ошибка инициализации камеры: 0x20004` / `0x105` | неверная распиновка (см. раздел выше), плохой контакт разъёма камеры, недостаточное питание |
| Серые полосы/артефакты на картинке | снизьте частоту `XCLK_FREQ_HZ` до `16000000` в `src/main.cpp` |
| PSRAM не находится, стрим медленный | проверьте, что в `platformio.ini` остались `qio_opi` и `-DBOARD_HAS_PSRAM` |
| Задержка/лаги видео | в коде уже включено `WiFi.setSleep(false)`; проверьте уровень сигнала WiFi |
| Монитор порта пустой | особенность этой платы: стартовый лог загрузчика приходит, вывод самой прошивки — нет. Отладка из кода убрана, адрес камеры смотрите через mDNS/роутер |

## Технические детали

- Ядро: arduino-esp32 2.0.17 (платформа `espressif32`); драйвер `esp32-camera`
  уже встроен в ядро — из реестра его добавлять не нужно. В `lib_deps` только
  WiFiManager (настроечная точка доступа).
- Сервер: `esp_http_server` из ESP-IDF, два экземпляра — порт 80 (страница и
  управление) и порт 81 (только бесконечный MJPEG-стрим). Приём OTA-прошивки —
  ArduinoOTA из состава ядра, обслуживается в `loop()`.
- Конфигурация N16R8: `board_build.arduino.memory_type = qio_opi`
  (16 МБ quad-flash + 8 МБ octal-PSRAM), таблица разделов `default_16MB.csv`.
